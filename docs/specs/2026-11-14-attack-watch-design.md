# Attack watch design

## Goal
Package the INFRA-640 handoff into `skills/attack-watch/`: a continuous defensive watch skill usable by Claude Code and Codex, four configurable observers and a bounded CF block helper. Preserve all meaningful operational constraints from `docs/handoff/attack-watch/HANDOFF.md`.

## Non-goals
No live monitoring, production writes, credentials retrieval, bot activation, release publishing, Jira closure or delivery to another session in this implementation. No autonomous API key revocation, deletion, credential rotation or blanket grants. Account disabling remains an exact SQL procedure executed by the agent through the project's ops workflow. No universal schema abstraction: the account adapter supports the handoff schema and configurable DB/table identifiers.

## Design
### Components and configuration
Python standard library scripts in the skill: shared config/HTTP/credential/event utilities; CF, ES, Sentry and account observers; CF block tool. One JSON example under `examples/` contains ccinfra resource names, store entry names, excluded egress, indexes, DB resources and clearly unconfigured zone/rule IDs; no secrets or hard-coded workspace paths. Shared schema validation fails closed for malformed config. Environment variable names and store metadata describe credentials; actual values enter only the process environment via the project's secrets workflow. No shell evaluation of config. Documentation explains store-to-env mapping and project-specific access adapters.

### Observer contract
Each observer supports `--config`, `--state-dir`, `--once`, and continuous mode (default 300s); emits JSONL events with UTC timestamp and source, heartbeat on each completed poll and source-specific ERROR on failure without raw remote responses or exception messages. State lives outside the skill in a private project incident directory; atomic writes, restart persistence and per-source files; one process per observer/state directory. A poll is bounded by network/subprocess timeouts. Errors do not advance checkpoints. Empty valid data is distinct from failed/malformed responses. Mark truncation or sampling explicitly, never claim exhaustive coverage. Observers never mutate production.

CF queries adaptive groups per configured zone and host in an overlapping 10-minute window. Events: CANDIDATE, KEY, RP-ENUM, AUTH-HIT, AUTH-WAVE, SESSION. Actual originResponseStatus >0 counts as origin; public API paths do not count as authenticated success. Auth failure-before-success requires ordered minute data; same-minute ambiguity is not asserted as ordered. Preserve country/IP/object ids only where needed, omit raw UA/path/query strings from events. Exempt egress is removed from candidates, while anomaly reporting remains visible. Thresholds, paths, scanner pattern and session endpoints configurable. Deduplicate repeated alerts with bounded persisted state; heartbeats remain visible. CF analytical evidence alone cannot prove breach or authorize action.

ES reads configured app/ingress/hostsec indexes with timestamp bounds and explicit limits; APP5XX at >=3, APPERR exception class/signature with no raw message, HOSTSEC rare rule keys and >=100 auth events by default. Ingress contributes an aggregate status signal. Sentry polls every configured project, emits new issues and >=20 count deltas, persists baseline and paginates within a bounded cap with a coverage warning; emits issue IDs/counts only (no request, user, vars or raw title). Accounts read bounded PG users pages with read-only SQL through configured tsh argv; report ids/company/epoch created/active/verified/wallet count and CH first login IP/country. Revisit recent accounts for delayed login/activation changes; commit checkpoints only after successful required enrichment; paginate without skipping. SQL identifier and numeric interpolation validated.

### Authority and lifecycle
SKILL.md includes startup, watch/classify/act/record/notify loop and end-of-reply status. Require an explicit scoped project grant recorded with owner, targets, allowed action types, expiry/review date, egress and notification destination; absent grant means observe only. Existing grant can be reused within its scope. Health, evidence, backup, bounded action, readback, 35-second propagation verification, health, changelog and Jira comment are required per mutation. Read references before their branch. Uncertain identity => profile first. Notifications only when owner should act, action taken, material access loss or breach evidence; routine heartbeats stay local. Supervisor checks stale heartbeats and Teleport expiry, renews Claude Monitor every 30 minutes or polls managed background output under Codex; no claim of continuous coverage across an ended agent turn. Stop and report gaps rather than silently going blind.

### Block helper
Exact IP only by default, optional narrowly scoped /64 only with recorded subscriber evidence and grant; ASN/UA/path clauses are prepared and applied manually through the documented CF procedure, not arbitrary-expression CLI input. All clauses include configured exempt egress exclusions. Explicit zone key and explicitly configured ordered rule IDs; enabled block rules only. Dry-run default; `--apply` requires live unexpired project IP grant, evidence reference, health hook success and owner egress configuration. Build structured IP clauses, reject overlap with exempt networks and unsupported ranges. GET full ruleset, unique private before snapshot per operation, select explicit rule with space (<4096 chars), second GET version guard, PATCH preserving action/description/enabled/parameters, GET after snapshot. Verify expression, stable fields, other rules and ordering while ignoring documented API version/timestamp changes. Retry GET transport failures only; ambiguous PATCH result => readback, never blind retry. CLI returns nonzero on mismatch, conflict or health failure. Local writer lock; Cloudflare has no guaranteed atomic compare-and-swap, so document residual concurrent remote-writer race and require incident writer coordination. Rollback removes only this exact clause using current state and the same change checks; never restores a full snapshot.

### Distribution and references
Installer already discovers skill directories. Register the new capability in README/USING only where needed for discovery, keep plugin metadata versions synchronized if changed; no release bump required for an unpublished feature branch. References split sources/access, signals, false positives/traps and action procedures. ccinfra-specific integrations route to combocards-ir/combocards-ops and keepass; skill workflow handoffs use bare plus verus-skills names for distro skills. Work Jira updates follow jira-cc-close-ticket where applicable. Browser work uses owner's authenticated Playwright only. No secrets or raw sensitive payloads in output, snapshots contain CF rules only.

## Testing
Offline fixtures/mocked HTTP/subprocess only. Tests cover config/credential redaction, cache vs origin, candidate thresholds/public endpoints/exemptions, minute ordering, key/session/recovery events, ES statuses/hostsec, Sentry state deltas, account checkpoint/enrichment/pagination/revisit, malformed/truncated sources, heartbeat/error behavior. Block tests cover dry-run no PATCH, grant/expiry/egress gates, IP overlap, explicit fallback IDs, size, version drift, idempotency, ambiguous PATCH readback, unrelated rule/order changes and health failure. Run Python unittest through a Node test wrapper so npm test exercises new scripts; run full npm test, Python compile and skill validator. Independent reviewer performs tabletop invocation with supplied fixtures for low-volume residential false positive, shared IPv6, new attacker account and stale Teleport. Verify install discovery includes attack-watch.
