# Spec review: Attack watch design
## Verdict
NEEDS CHANGES — detection semantics, account progress, coverage recovery and mutation authorization need concrete contracts before planning.
## Findings (confidence 7+)
[P1] (confidence: 10/10) docs/specs/2026-11-14-attack-watch-design.md:16 — “Thresholds, paths, scanner pattern and session endpoints configurable” does not define the default CANDIDATE predicate or AUTH-WAVE threshold, and the two supplied authorities disagree: HANDOFF.md:49–50 requires two threshold signals or scanner UA plus bad path, whereas tools/detect.py also accepts bad>=2 alone and counts cached nonblocked requests as origin. Generalizing the script and implementing the handoff produce different alerts — specify the Boolean predicate, numeric defaults, success status range and fingerprint prerequisite for SESSION; explicitly make the handoff defaults authoritative and test each boundary and the legacy bad-path-only false positive.
[P1] (confidence: 9/10) docs/specs/2026-11-14-attack-watch-design.md:18 — Account startup position, recent-account horizon and required-enrichment semantics are undefined. Starting at zero can scan the production users history; treating a valid empty CH result as failure can stall all later accounts; expiring revisits too early loses delayed login/activation changes — define an explicit initial cursor/lookback, keyset ordering, page and per-poll budgets, empty-login success, per-account pending enrichment and a bounded persisted revisit policy; specify what happens when a revisit expires without login.
[P1] (confidence: 9/10) docs/specs/2026-11-14-attack-watch-design.md:14–16 — “Errors do not advance checkpoints” does not recover CF coverage when every query is the latest ten minutes. A fifteen-minute outage or restart permanently drops traffic despite retaining state; “Stop and report gaps” never defines how that lost interval is detected — persist successful coverage bounds and either catch up in bounded windows or emit a precise unrecoverable-gap event before resuming; define equivalent recovery rules for ES and Sentry and verify an outage longer than the normal window.
[P1] (confidence: 9/10) docs/specs/2026-11-14-attack-watch-design.md:21–24 — “expiry/review date” permits either a hard expiry or an advisory review date, but --apply requires a “live unexpired project IP grant.” No machine-readable grant input or scope-matching contract connects those requirements, and the /64 subscriber evidence has no defined input — specify the grant schema/reference, mandatory UTC expiry, project/zone/action/range matching, owner-egress binding and separate subscriber-evidence reference; reject advisory-only, malformed, wrong-zone and expired grants before PATCH, including rollback authorization rules.
[P1] (confidence: 8/10) docs/specs/2026-11-14-attack-watch-design.md:21–24 — The lifecycle requires post-change health and 35-second propagation verification, but the helper only specifies a health hook success gate and immediate API readback. A successful PATCH/readback can be reported as complete without checking edge enforcement, and a timeout after PATCH can leave an applied change without a defined incomplete-operation record — assign each step to helper or supervising agent, define bounded hook argv/input/result contracts, and persist applied/verified/incomplete status with the operation reference. Define the delayed CF verification and post-health result required before success; on uncertainty, read back and report the unresolved change without blind retry or snapshot restore.
[P1] (confidence: 9/10) docs/specs/2026-11-14-attack-watch-design.md:24 — Moving ASN/UA/path changes to a manual procedure does not explicitly retain the handoff's action-specific gates: attacked-zone-only ASN scope, seven-day legitimate-UA check and partner-host protection, and path rules requiring both absent session cookie and absent Authorization with three verification cases (HANDOFF.md:74–76). A generic “documented CF procedure” can preserve backup/readback while losing these authorization constraints — require those exact gates in the references and tabletop checks; this implements the existing Decisions: Owner scope (user) preservation requirement without changing its authority envelope.
[P2] (confidence: 8/10) docs/specs/2026-11-14-attack-watch-design.md:14–18 — Per-request timeouts do not bound a poll containing arbitrarily many account pages or configurable projects/zones, and only Sentry has an explicit pagination cap. A busy account stream can prevent completion and heartbeat indefinitely while each subprocess finishes on time — define a poll deadline and request/page budgets for every observer, resumable continuation state and coverage-warning semantics on budget exhaustion; reserve a bounded revisit budget so new accounts cannot starve revisits.
[P2] (confidence: 9/10) docs/specs/2026-11-14-attack-watch-design.md:14–21 — “heartbeat on each completed poll” and “source-specific ERROR” leave partial success undefined: ES can reach app logs while hostsec fails, or CF can reach one zone while another fails. A supervisor watching only process heartbeats can silently treat the failed target as healthy — define per-target coverage and last-success fields, partial/error heartbeat semantics, stale thresholds and the affected-target notification; test one failed target alongside a continuously successful sibling.
[P2] (confidence: 9/10) docs/specs/2026-11-14-attack-watch-design.md:30 — The verification list omits several explicit contracts: rollback preserving intervening edits, local lock contention, restart persistence and atomic-write failure, private file permissions, GET-only retry behavior, and lifecycle notification/recording gates. The four tabletop cases do not exercise these — add Python unittest fixtures for add A/add B/rollback A retaining B, competing local writers allowing one PATCH, interrupted state replacement retaining valid old state, private state/snapshot modes, and GET failure versus ambiguous PATCH; add a node:test documentation/tabletop check for lifecycle order and notification suppression.
[P2] (confidence: 10/10) docs/specs/2026-11-14-attack-watch-design.md:30 — “skill validator” names no executable, path or expected result. package.json and Makefile define no skill-validation command; tests/plugin.test.mjs invokes the distinct `claude plugin validate` and conditionally skips it — name a reproducible skill validator and its availability requirements, or define a repository-local node:test check for attack-watch frontmatter, referenced paths and packaged files; state the command and passing result.

## Section notes
### 0. Scope challenge
Existing reuse: detect.py supplies CF aggregation and signal extraction; anomaly.py supplies ES/Sentry queries; es.py supplies the HTTP access pattern; newusers.sh supplies PG/CH schema queries; irblock.py supplies the ruleset mutation sequence; ipprofile.py supplies profiling queries. These are reference code, not installable dependencies: several import an absent ccinfra cf-watch.py through a hard-coded workspace path. Reuse their query logic and fixtures while replacing access/state handling. The minimum deliverable remains one skill, shared utilities, four observers, one bounded helper and references/tests; independent forensic tooling and supervisor automation beyond the documented agent loop can be deferred. Although this exceeds eight files, four thin adapters over shared polling/state/HTTP primitives are the smaller version that retains the Goal; no new service or class hierarchy is necessary. Standard-library urllib, subprocess, ipaddress, tempfile/os.replace and platform locking should supply the basic mechanisms. Completeness problems are the missing recovery/budget contracts and omitted failure tests listed above. Distribution needs no parallel installer: scripts/install.mjs discovers SKILL.md directories, and the Codex plugin already exposes ./skills/. Publishing is explicitly deferred in Non-goals.
### 1. Requirements
Detection defaults, first-run/revisit behavior, target-level health and mutation completion need definitions. “expiry/review date” has two operational readings: expiry prohibits subsequent use, while review date merely requests review; the helper needs the former. “Stop and report gaps” can mean terminate the observer or continue unaffected sources while reporting lost coverage; define the intended behavior and checkpoint consequences. Account-disable SQL and its read/transaction/returning/readback sequence already exist in HANDOFF.md:77,101–102 and should be copied into the promised procedure. No live operational authority is granted by this implementation request.
### 2. Scope
No issues found. The observers, shared contract, helper and references form one packaging task; four services are not being introduced. Manual ASN/UA/path procedures and account disabling are compatible with excluding their automated helpers. Release publishing, bot activation, credentials retrieval and live production activity are explicitly outside this implementation. Preserve the action-specific safeguards identified above within the existing scope.
### 3. Feasibility
The installer claim is verified at scripts/install.mjs:43–46; package.json uses node:test and has no extra Python dependencies. Runtime portability is feasible with the standard library. CF can fail or truncate per zone: error/sampling warnings are specified, but coverage recovery and partial-target health are incomplete. ES can return valid app data while ingress/hostsec fails: safe errors are specified, but healthy process heartbeats need target coverage. Sentry can exceed its page cap: the design explicitly requires a coverage warning and persisted baseline. PG can succeed while CH times out: checkpoint retention is specified, but empty enrichment and forward progress need rules. Teleport can expire: reporting and supervision are specified, but stale thresholds and target states are missing. HTTP PATCH can succeed before its response is lost: readback without blind retry is specified; the remaining verification/recording outcome is incomplete. Local concurrent writers are locked and remote races are expressly acknowledged. State replacement can fail or a process can restart: atomic persistence is specified but lacks concrete failure verification. Store-to-env access and authenticated Playwright are documented integration routes; this review neither retrieves credentials nor invokes them.
### 4. Testability
The proposed Node wrapper can run Python unittest within the existing `node --test tests/*.test.mjs` harness, and the listed fixtures cover ordinary signals, redaction, malformed responses, pagination, source errors and most block gates. To make the findings verifiable, add named cases: candidate_bad_paths_alone_is_not_candidate; account_empty_login_advances_and_revisits; restart_after_fifteen_minute_gap_reports_interval; grant_wrong_zone_or_review_only_never_patches; applied_change_requires_delayed_verification_and_post_health; poll_budget_yields_with_continuation; and partial_zone_failure_remains_stale_despite_heartbeat. Each uses fake time and mocked HTTP/subprocess, with explicit expected events, state and PATCH counts. Add the rollback/locking/persistence/retry cases above and tabletop checks rejecting shared /64, unverified UA and overbroad path rules. Install discovery can be checked by importing skillDirs and exercising linkSkills against a temporary target, following tests/install.test.mjs. No tests or builds were run during this review.
### 5. Decisions
No issues found. Decisions: Runtime (auto) is consistent with the Python reference scripts and with a standard-library implementation; replacing their hard-coded external imports is already required by the Design. Decisions: Owner scope (user) is workable in this checkout and explicitly withholds operational authority. The findings request precise implementation and preservation of that decision, not a different runtime or a wider grant.
