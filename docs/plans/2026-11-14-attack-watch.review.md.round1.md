## Section notes
### 1. Architecture
The failure paths evaluated are CF analytics failure/sampling, independent ES query failure, Sentry page truncation, PG success followed by CH failure, PATCH ambiguity/version drift, hook failure and rollback after another edit. Partial status, GAP reporting, checkpoint retention, explicit coverage warnings and coordinated remote writers address the stated source failures. Hard I/O bounds, operation identity and restart after a remote write remain unspecified as identified above. Config validation and pure detectors provide useful boundaries, but operation records need a defined schema with legal lifecycle transitions; a small apply/recovery/rollback state diagram should make those transitions reviewable. Native skill discovery and documentation integration cover the new packaged artifact without requiring a release in this scope.
### 2. Code quality
The unresolved journal states allow an invalid relationship between a successful remote write and a local `already_present` outcome. Define recovery centrally alongside operation persistence rather than separately in apply and rollback. Shared polling, safe error classes, environment-only credentials, explicit rule selection, live-state rollback and preservation of writable rule fields otherwise address the principal duplication and error-handling risks. The Task 1 commit allowlist should explicitly include tests/plugin.test.mjs and the temporary SKILL.md when its registration fallback is used; those files are currently assigned to Task 2 despite being necessary for Task 1's full-suite verification. README/USING and packaged references are explicitly scheduled for updates.
### 3. Tests
The repository uses node:test, with the plan adding unittest discovery through a Node wrapper. Planned cases exercise CF predicates and minute ordering; ES access/error/ingress/hostsec; Sentry new/delta/persistence/caps; account scan/enrichment/revisit/reconciliation; shared config/state/coverage; and mutation gates, drift, ambiguity, health, verification, rollback and local locking. Missing concrete behavioral cases are the slow-body/size boundary, cross-zone operation replay, fresh-process recovery after remote write, and account backlog throughput described above. Sentry continuation metadata also needs confirmation and a transport-level fixture. Tabletop fixtures should execute the documented authority/lifecycle decisions, including denial outcomes, rather than merely search for words. No tests or builds were run for this review.
### 4. Performance
Per-user CH requests are the material external-call bottleneck introduced into the expanded scan/revisit workload; batching and fair continuation need to be part of the plan. Unbounded HTTP bodies also undermine memory and deadline guarantees even though row/page counts are bounded. The remaining planned target caps, bounded dedup state, pagination limits, private persisted continuation and reserved revisit budget address the stated growth risks; no additional caching or indexes are justified by the supplied material.
