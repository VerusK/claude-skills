# Claude Code and Codex runtime

Read this when a distro skill delegates work or launches a long command.
Use the tools exposed by the current host; tool names in examples describe
operations, not a requirement to install another runtime.

## Load a skill and its resources

Claude Code uses its Skill tool. In Codex, read the selected `SKILL.md` from
the catalog path and follow it; a hand-off means loading the next skill,
not sending a slash command to a shell. Resolve relative references from
the loaded file, including through symlinks, never from the target repo.

The distro root is two physical directories above `skills/<name>/`.
Fill each shell block's `SKILL_DIR` from the loaded skill's catalog path
or the base directory returned by Claude's Skill tool. Shell variables
are local to one call: repeat this binding in each call that needs it.
If that version is missing, report the missing path instead of using
another installation. `~/.verus-skills/root` is only a legacy pointer for
older releases; current skills do not use it.

## Delegate a role

Use one source of role instructions: `agents/verus-<role>.md` in the same
distro as the loaded skill. Roles are `worker`, `reviewer`, and `explorer`.

- **Claude Code:** dispatch with the corresponding `subagent_type`
  (`verus-worker`, `verus-reviewer`, `verus-explorer`; prefix
  `verus-skills:` in the plugin). Use background subagents without the
  optional teammate `name`. Their model and effort come from the agent
  definitions generated by `make models`.
- **Codex:** load the role file as data, remove its YAML frontmatter, and
  prepend its body to the task prompt. Include the absolute path of this
  adapter and tell the child to use its Codex command/session mapping for
  Claude tool terms in the role or task template. Dispatch with the available native
  subagent tool (`spawn_agent` where exposed), without model/effort
  overrides unless the user requests them. Claude's `model: opus` and
  `effort:` metadata are not Codex settings. Codex uses its host defaults.
  When supported, request a fresh context (`fork_turns="none"`); provide
  the task, absolute worktree path, branch and necessary constraints.
  A required `task_name` or task label is fine: the Claude teammate naming
  restriction does not apply to it. If the host always forks history,
  disclose that isolation is limited and provide a self-contained brief.

Role instructions bind the child along with its task. Workers implement
and self-review; reviewers write only the named report; explorers are
read-only. Each role's no-delegation rule prevents recursive workflow
activation: a dispatched task is not a new kickoff. Pass the distro/role
path explicitly when the child cannot inherit discovery context.

Record the returned agent ID. Await its output with the host's wait tool,
and answer child questions using its message/follow-up tool. Resume that
same ID for fixes when the workflow calls for it. Retain an implementer
until its task review is settled; close/release finished agents when the
host exposes that operation. If subagents are unavailable, report that
limitation before selecting a documented fallback; do not silently count
a self-review as an independent review.

## Commands and progress

Use the host's shell tool and keep the target repo's cwd explicit.
In Codex, start long commands with a short yield and retain the returned
session/cell ID; poll with the matching tool until completion. A yielded
command is still running. Claude's `run_in_background` and
`dangerouslyDisableSandbox` are not Codex shell arguments. Respect the
current sandbox and approval policy; request escalation only when that
host permits it and the action needs it.

Track tasks with the host's plan/task tool when available. The SDD ledger
remains the durable record across compaction. Use bounded waits and the
host's progress cadence; keep users informed while a child or command is
running. Report the actual exit code and output before proceeding.
